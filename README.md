# VEX Team 308A – Turning Point (2018–2019) Robot Code

RobotC program created by members of **VEX Robotics Team 308A** of **North Gwinnett High School** for the **VEX Robotics Competition: Turning Point (2018–2019 season)**.

It runs a VEX Cortex (VEX2 platform) robot with a 4-motor drivetrain, a ball intake, and a catapult launcher. It follows the standard VEX competition template (`pre_auton`, `autonomous`, `usercontrol`), and the autonomous routine appears to be a **Programming Skills** run on the Turning Point field (flags, caps, platforms).

## Program Structure

### `pre_auton()`
Runs before the match. Stops tasks between modes and **calibrates the gyro**: sets it to `sensorNone`, waits 1 s, re-enables it, then waits 2 s. **Keep the robot still** during this time.

### `task autonomous()`
Runs a scripted skills routine (see [Autonomous Routine](#autonomous-routine)). Uses boolean flags (`RightTurn`, `LeftTurn`, `motorbrake`, `Intake`, `FireCata`) to trigger helper behaviors:

| Flag | Behavior |
|------|----------|
| `RightTurn` | Spin right ~90° using the gyro (`-900`), then brief reverse pulse to brake |
| `LeftTurn` | Spin left ~90° using the gyro (`900`), then brief reverse pulse to brake |
| `motorbrake` | Reverse all drive motors at -20 for 250 ms, then stop |
| `Intake` | Run intake at 120 until `SonarBall` reads < 3 mm (ball captured) |
| `FireCata` | Fire catapult (120 for 1 s), then retract until `CatapultSwitch` is pressed |

### `task usercontrol()`
Driver-controlled loop: catapult control, drive mixing, and intake.

## Driver Controls

| Input | Action |
|-------|--------|
| **Ch3** (left stick, vertical) | Forward / backward (`motorspeedL`) |
| **Ch4** (left stick, horizontal) | Turning (`motorspeedR`) |
| **Btn6U** | Intake in (120) |
| **Btn6D** | Intake out (-120) |
| **Btn8D** | Fire catapult |

**Drive mixing:**
```
Left motors  = Ch3 + Ch4
Right motors = Ch3 - Ch4
```
Both inputs are clamped to ±110.

**Catapult logic:** The catapult motor runs (retracts) at 120 whenever the touch switch is *not* pressed, and stops when the switch is pressed (fully loaded). Pressing **8D** while loaded sets `ReadyFire` and runs the motor to release a shot; releasing the button re-arms it.

## Autonomous Routine

Intended sequence (field distances as noted in code comments; encoder scale is **90 ticks/inch**):

1. Fire catapult – high flag #1
2. Drive forward 40" – low flag #2 → brake
3. Drive backward 40" to start position → brake
4. Turn right 90°
5. Drive forward ~47–48" to flip Cap #3, intake ball under it → brake
6. Turn left 90°
7. Fire – high flag #2
8. Drive forward 40" – low flag #3 → brake
9. Drive backward 23.5" → brake
10. Turn right 90°
11. Reverse intake, drive forward 47" to flip Cap #2 → brake
12. Turn right 90°
13. Drive forward 23.5" (down the field) → brake
14. Turn right 90°
15. Intake, drive forward 23.5" to Cap #4 → brake
16. Drive backward 70" to blue top starting point → brake
17. Turn right 90°
18. Fire – high flag #3
19. Drive forward 40" – low flag #3 → brake
20. Drive backward 63.5" to align with platforms → brake
21. Turn right 90°
22. Drive backward at full power (-120) for 2.5 s to climb the center platform, then stop

## Building & Running

1. Install **RobotC for VEX Robotics** (Cortex).
2. Open the `.c` file and connect the Cortex via USB or VEXnet.
3. Select **Robot → Platform Type → VEX Cortex** and **Competition Mode**.
4. **Compile and Download** the program.
5. For testing, use the **Competition Control** window (Robot → Debugger Windows), or a field control / competition switch.
6. Let `pre_auton` finish (~3 s, robot motionless) before starting the match.

## Known Issues & Suggested Fixes

The autonomous code in its current form **will not behave as the comments describe**. Main problems:

1. **Flags are checked only once, at the top.** The `if (RightTurn == true)` etc. blocks run *before* any flag is set, so they never execute. The flags set later in the routine are never acted on. Convert these blocks into **functions** and call them in sequence, e.g. `turnRight90()`, `driveForward(inches)`, `fireCatapult()`.

2. **No waiting for movement.** After setting motor power, the code immediately checks the encoder once (`if(SensorValue[LeftEncoder] == ...)`) and moves on. Use a **`while` loop** with a comparison, e.g.:
   ```c
   while (abs(SensorValue[LeftEncoder]) < inches * 90) { }
   ```

3. **Exact equality comparisons (`==`) on sensors.** Encoders and gyros can skip values. Use `<`, `>`, or `abs()` comparisons.

4. **Gyro turn uses `if` instead of `while`.** Same issue — wait in a loop until the gyro reaches ±900 (tenths of a degree).

5. **Encoder not reset between moves.** Reset `SensorValue[LeftEncoder] = 0` before each drive segment; otherwise distances are cumulative.

6. **Backward drive checks `== 0`.** Compare against `-distance` (or use `abs`) after resetting the encoder.

7. **Motor power > 127.** Values like `120` are fine, but be aware VEX motor range is -127 to 127.

8. **Reverse-braking at the end of the Cap #2 move:** intake is set to `-120` before the drive but only stopped inside the `if`, which may never fire.

9. **Missing closing brace.** `task usercontrol()` ends without a closing `}` for the function (the `while(true)` loop is closed, the task is not). This will cause a compile error — add one more `}` at the end of the file.

10. **Catapult fire logic in autonomous** duplicates the same retract block twice and uses `wait1Msec(1000)` before checking the switch; consider a single `while (SensorValue[CatapultSwitch] == 0)` retract loop.

11. **Unused items:** `RightEncoder` (only reset), `Sonar`, `SensorScale[Gyro]` (commented out).

12. **Driver control catapult:** the first `if/else` block sets the motor every loop; the `Btn8D` block sets it to 120 and then the next loop iteration may override it. Verify firing behaves as intended on the real robot.

### Suggested refactor (example)

```c
void driveInches(int inches, int power)
{
    SensorValue[LeftEncoder] = 0;
    int target = inches * 90;
    int dir = sgn(power);
    motor[LeftMotor1] = motor[LeftMotor2] =
    motor[RightMotor1] = motor[RightMotor2] = power;
    while (abs(SensorValue[LeftEncoder]) < target) { wait1Msec(5); }
    // brake pulse opposite direction
    motor[LeftMotor1] = motor[LeftMotor2] =
    motor[RightMotor1] = motor[RightMotor2] = -dir * 20;
    wait1Msec(250);
    motor[LeftMotor1] = motor[LeftMotor2] =
    motor[RightMotor1] = motor[RightMotor2] = 0;
}

void turnDegrees(int tenths, int power)   // tenths of a degree, e.g. 900
{
    SensorValue[Gyro] = 0;
    motor[LeftMotor1]  = motor[LeftMotor2]  =  power;
    motor[RightMotor1] = motor[RightMotor2] = -power;
    while (abs(SensorValue[Gyro]) < tenths) { wait1Msec(5); }
    motor[LeftMotor1] = motor[LeftMotor2] = motor[RightMotor1] = motor[RightMotor2] = 0;
}
```

## Tuning Constants

| Constant | Value | Meaning |
|----------|-------|---------|
| Encoder ticks per inch | `90` | Calibrate for your wheel size/gearing |
| Gyro 90° turn | `±900` | Gyro units are tenths of a degree |
| Brake power / time | `-20` / `250 ms` | Reverse pulse after movement |
| Intake speed | `120` | Out of 127 |
| Ball detect distance | `< 3` mm | `SonarBall` threshold |
| Catapult power | `120` | Out of 127 |
| Drive clamp (driver) | `110` | Max stick-input magnitude |
| Final platform push | `-120` for `2500 ms` | Climb center platform |
